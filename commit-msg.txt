fix(store): check the schema version before probing for the runs table

From review on #359: the runs probe ran before the version check, so a store from a newer build
that renamed or dropped the runs table was reported as "not a neatroots store (no runs table)"
instead of being refused with the message that says to update neatroots. The probe still runs for
a store whose version this build can read, which is what tells a non-neatroots database apart.

Test: a store with the runs table dropped and meta.schema_version bumped is refused with the
version message and does not throw the probe's message. On b705fb6 it failed with the assertion
that expected the version message but got the probe's.
